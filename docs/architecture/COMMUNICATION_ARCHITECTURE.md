# Communication Architecture

## Overview

This document defines how all components in the platform communicate — both internal (service-to-service) and external (platform-to-provider and provider-to-platform). It covers protocols, patterns, timeout policies, and connection management.

---

## Communication Patterns

| Pattern | Used For | Protocol |
|---------|----------|----------|
| Synchronous Request-Response | Client app → Gateway, Gateway → Provider | HTTPS/REST |
| Server-Sent Events (SSE) | Gateway → Admin Console (real-time updates) | HTTP/1.1 persistent connection |
| Webhook (inbound) | Provider → Webhook Service | HTTPS POST |
| In-process function call | Gateway → packages/* | Node.js function call |
| Database read/write | Services → Neon PostgreSQL | PostgreSQL wire protocol (TLS) |

The platform deliberately avoids:
- Message queues (RabbitMQ, SQS) — adds operational complexity not justified at current scale
- gRPC — no binary protocol benefit for this use case
- GraphQL subscriptions — SSE is simpler for unidirectional server-push
- WebSockets — bidirectional not needed; SSE is sufficient for dashboard

## External Communication: Client Apps → Gateway

### Protocol
- HTTPS only (TLS 1.2+)
- HTTP/1.1 (HTTP/2 upgrade considered future)

### Headers
```
X-API-Key: bap_live_<key>          (required)
X-Request-ID: <uuid>               (optional — generated by gateway if absent)
Content-Type: application/json
```

### Timeout Policy
- Client apps should set a 30-second request timeout
- Gateway enforces a 30-second maximum processing time per request
- If provider call times out within those 30 seconds → retry logic activates

### Response Format
```json
// Success
{
  "id": "tx_abc123",
  "status": "success",
  "provider": "stripe",
  "latency": 142,
  "decisionReason": "Routed via weight allocation. Selected: Stripe.",
  "response": { ... }
}

// Error
{
  "error": {
    "code": "PAYMENT_PROVIDER_UNAVAILABLE",
    "message": "Payment processing temporarily unavailable.",
    "request_id": "req_xyz789"
  }
}
```

## External Communication: Gateway → Providers

### HTTP Client Configuration (packages/http-client)

All outbound provider calls use a shared Axios instance with:

```typescript
const client = axios.create({
  timeout: 15_000,            // 15 second socket timeout
  maxRedirects: 0,            // Never follow redirects from providers
  validateStatus: null,       // Handle all status codes in our code, not Axios
  headers: {
    'User-Agent': 'company-api-platform/1.0',
    'X-Request-ID': requestId  // Propagated from inbound gateway request
  }
});
```

### Retry Policy (per provider call)

```
Attempt 1: immediate
Attempt 2: 100ms delay  + 0-50ms jitter
Attempt 3: 200ms delay  + 0-100ms jitter
Attempt 4: STOP — escalate to circuit breaker, try next provider
```

Retryable errors:
- HTTP 429 (rate limit) — with `Retry-After` header respected
- HTTP 500, 502, 503, 504 (server errors)
- Network timeout (ECONNRESET, ETIMEDOUT, ECONNREFUSED)

Non-retryable errors (returned immediately, no retry):
- HTTP 400 (bad request — our request is malformed)
- HTTP 401, 403 (auth failure — retrying won't help)
- HTTP 402 (payment required — card declined)
- HTTP 404 (resource not found)

## Internal Communication: In-Process Libraries

`services/api-gateway` imports and calls `packages/routing`, `packages/providers`, `packages/database` directly as Node.js module imports. There is no network boundary.

```typescript
// Direct in-process call — zero network overhead
const event = await routingEngine.routePayment(appId, payload);
```

This is a deliberate design choice. See [ADR-004](../adr/ADR-004-orchestration.md).

## External Communication: Providers → Webhook Service

### Protocol
- HTTPS POST to `https://webhooks.company.com/webhooks/:provider`
- Provider sends JSON body (or form-encoded for legacy providers)
- Platform returns HTTP 200 within 5 seconds (provider requirement)

### Body Parsing
```typescript
// Webhook routes use raw body parser — REQUIRED for signature verification
app.use('/webhooks', express.raw({ type: '*/*' }));

// All other routes use JSON parser
app.use('/api', express.json());
```

## Database Communication

### Connection Management
```
services/api-gateway:    Prisma connection pool (max 5 connections)
services/webhook-service: Prisma connection pool (max 3 connections)
services/worker:         Prisma connection pool (max 2 connections)
Total:                   Max 10 connections (well within Neon's limits)
```

### TLS
All connections to Neon use `sslmode=require`. Certificate validation is on.

### Query Timeout
```typescript
// All Prisma queries have a 10-second timeout
prisma.$use(async (params, next) => {
  return Promise.race([
    next(params),
    new Promise((_, reject) => 
      setTimeout(() => reject(new Error('DB query timeout')), 10_000)
    )
  ]);
});
```

## SSE Connection Management

### Server-Side
```typescript
// Gateway sets headers and holds connection
res.writeHead(200, {
  'Content-Type': 'text/event-stream',
  'Cache-Control': 'no-cache',
  'Connection': 'keep-alive',
  'X-Accel-Buffering': 'no'  // Nginx: disable buffering for SSE
});

// Keepalive every 30 seconds to prevent proxy timeouts
const keepalive = setInterval(() => {
  res.write(`data: ${JSON.stringify({ type: 'ping' })}\n\n`);
}, 30_000);

req.on('close', () => {
  clearInterval(keepalive);
  eventBus.unsubscribe(listener);
});
```

## Latency Budget

| Segment | Budget | Actual (P95 target) |
|---------|--------|---------------------|
| Client → Gateway (network) | < 50ms | Depends on client location |
| Gateway auth + validation | < 5ms | ~2ms |
| DB idempotency check | < 10ms | ~5ms |
| DB transaction insert | < 10ms | ~5ms |
| Routing decision | < 1ms | ~0.1ms |
| Provider API call | < 2000ms | Varies by provider |
| DB transaction update | < 10ms | ~5ms |
| SSE event emit | < 1ms | ~0.1ms |
| **Total (gateway overhead)** | **< 36ms** | **~18ms** |
| **Total (incl. provider)** | **< 2036ms** | **~500ms P95** |
